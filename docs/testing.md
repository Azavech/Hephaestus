---

The tests are package tests of `HephaestusKit` ([architecture.md](architecture.md#hephaestuskitpackageswift)), written
with XCTest and run on macOS. Every test file of the repository is listed above; a test file is added here before it is
written. The code under test is specified by the docs named in each section; the expected values below come from those
docs, and when a doc and this file disagree, the doc wins and this file is corrected.

## Test targets

| Target                | Depends on                                      | Content                                                                                                                                                              |
|-----------------------|-------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `HephCoreTests`       | `HephCore`                                      | YAML files, validation, task ids, envelope coding, docs hash, search matching, Claude folder names, migration journal, Keychain credential store                     |
| `HephNetTests`        | `HephNet`, `HephCore`                           | Mesh key derivation, TLS-PSK WebSocket transport and pairing on 127.0.0.1                                                                                            |
| `HephHostTests`       | `HephHost`, `HephClient`, `HephNet`, `HephCore` | Claude CLI parsing and answers, MCP server, skills, migration and its recovery, uploads and ranged reads, comments, personal data check, Forge push gate, end to end |
| `HephEditorTests`     | `HephEditor`, `HephCore`                        | Syntax highlighting of Swift, Go, Markdown, YAML and JSON                                                                                                            |
| `HephClientTests`     | `HephClient`, `HephNet`, `HephCore`             | Workspace: presence, connections, stores, selections, previews, transfers; transcript and its paging; project paths and line selection; ANSI stripping               |
| `HephUISnapshotTests` | `HephUI`, `HephHost`, `HephClient`, `HephCore`  | One PNG per section of the preview workspace except Web, drawn off screen by an `NSHostingView` (macOS); the sidebar comes out blank                                 |

`HephHostTests` bundles `Fixtures/` as a resource (`.copy("Fixtures")`); a test reads a fixture with
`Bundle.module.url(forResource: <name>, withExtension: "jsonl", subdirectory: "Fixtures")`.

## Running

| Command                                                       | Runs                                                                            |
|---------------------------------------------------------------|---------------------------------------------------------------------------------|
| `scripts/test.sh`                                             | Every test ([forge/ci.md](forge/ci.md#scriptstestsh)), from the repository root |
| `scripts/test.sh --filter HephCoreTests`                      | One target; the arguments go to `swift test`                                    |
| `scripts/test.sh --filter EndToEndTests`                      | One test class                                                                  |
| `HEPH_LIVE_CLAUDE=1 scripts/test.sh --filter LiveClaudeTests` | The live Claude test (never in CI)                                              |

`scripts/test.sh` runs `swift test --package-path HephaestusKit --scratch-path build/SwiftPM`; the build products stay
in the ignored `build/` folder.

## CI

The `build` job of [forge/ci.md](forge/ci.md) runs `scripts/test.sh` on the `xcode-27` runner before the builds; a
failing test fails the job and nothing is built or released. In CI `HEPH_LIVE_CLAUDE` is unset, so `LiveClaudeTests`
skips, and the snapshot PNGs are written but never compared with reference images.

## Rules for every test

- XCTest: one `final class <File name>: XCTestCase` per test file (support files hold helpers only), test methods
  `test<Case>()`, `async throws` where they await. Tests of main-actor types are `@MainActor`.
- Every file of `HephHostTests` and `HephUISnapshotTests`, imports included, is wrapped in `#if os(macOS)` … `#endif`.
- Tests use `@testable import` of the module under test.
- No network beyond 127.0.0.1, no Bonjour, no Keychain, no signing, no Claude CLI (`LiveClaudeTests` excepted: it runs
  the CLI, which uses the network), no file outside a temporary folder, the Trash included: each test creates its
  folders under `FileManager.default.temporaryDirectory` with a UUID in the name and removes them in a teardown block.
  `ScreenSnapshotTests` is the exception: it writes its PNGs to `$TMPDIR/HephaestusSnapshots/`, which stays
  ([HephUISnapshotTests](#hephuisnapshottests)).
- Listeners bind 127.0.0.1 port 0 and use the port they got: a `WebSocketListener` is created with `port: 0` and
  `host: "127.0.0.1"` ([devices/mesh.md](devices/mesh.md#websocketlistener)), a `HostService` with the `HostOptions` of
  `TestHost` ([services/host.md](services/host.md)).
- No fixed sleeps: a test waits for a condition, polling every 10 ms, and fails after 5 s (15 s for events that come
  from FSEvents, 120 s for the answer of `LiveClaudeTests`). `ScreenSnapshotTests` is the exception: it runs the main
  run loop for 1 s before it draws each section ([HephUISnapshotTests](#hephuisnapshottests)).
- Values are compared as values: JSON as parsed objects (`JSONSerialization`), YAML as decoded files, never as raw
  strings unless a doc gives exact bytes.
- The repository is public and passes its own personal data check ([public-repository.md](public-repository.md)), its
  tests and this doc included. A test that needs personal data plants a fictional value it assembles at run time from
  pieces (for example `"/Us" + "ers/" + "jdoe"`), so that no line of a source file matches a rule of the check. Its
  output is never compared with or printed as the planted value. The pieces are only for the planted values this doc
  lists: a real value is never split, encoded, escaped or reformatted to get past a finding.
- `PublicCheckTests` and `ForgePushTests`, which run git and the personal data check, give every git and check
  process they run, and the git commands of the code they test, the environment of their `GitSandbox`
  ([Support files](#support-files)), never the user's: its own home folder, no global or system git configuration, a
  no-reply identity, and the private terms the case chooses. The `testRegister…` cases of `ForgePushTests` pass it to
  `registerSourceProject(_:environment:)` ([forge/pipeline.md](forge/pipeline.md#swift-api)); the `TestHost` they
  start runs, like every host, the capture of the login environment
  ([claude/cli.md](claude/cli.md#11-login-environment)). A case that plants a value in the e-mails of a commit replaces
  those variables for that one command (`git(_:in:environment:)`).
  `DocsHashTests` runs `scripts/docs-hash.sh`, which runs no git, with `/bin/bash` in the test process's environment.

Each test target is its own module, so a helper used by several targets is written in each of their support files,
with the same definition (`testCredentials` as in `NetTestSupport.swift`).

`waitUntil(timeout:_:)` polls its condition every 10 ms; when it does not hold within `timeout` (5 s by default), it
fails the test and throws `WaitTimedOut`.

`FakeMain` (main actor) serves the server end of a `LoopbackChannel` pair with an `RPCPeer`: it answers `hello` with a
configured `DeviceInfo` and `MeshSnapshot`, or with a configured error, after emitting on that connection the events of
its `eventsBeforeHello` list (empty by default); answers the methods it was given canned results for (by method name),
in order, optionally after a delay, a canned result being a result or a `ProtocolError`, and answers again with the
last canned result of a method once its queue is empty; answers other methods with `notFound`; records every request it
receives (method and params JSON); emits events on demand; can send `mesh.rekey`; can close its end.

`TestEnvironment.make(fakeMains: [String: FakeMain], credentials:, registry:)` returns a `TestEnvironment` (a class)
whose `environment` is a `WorkspaceEnvironment` ([client/workspace.md](client/workspace.md#workspaceenvironment)):
`openChannel` connects to the `FakeMain` registered under the URL's host (throws `unavailable` for other hosts), with
in-memory credentials and registry whose saves are recorded, `browse` reporting a list of `BonjourAdvert` the test
controls (`setAdverts(_:)`), `sleep` recording each duration and returning at once, `now` returning
2026-10-29T21:00:00.000Z, and an `attachmentCache` on a temporary folder (`AttachmentCache(root:)`). The
`TestEnvironment` exposes the recordings (`savedCredentials`, `savedDevices`, `sleeps`, `openedHosts`). After
`holdSleeps(true)` a sleep is recorded and then waits until `releaseSleeps()` or `holdSleeps(false)`
(`heldSleepCount` counts the waiting ones), so a test can check a state that lasts only during a sleep.
`removeFiles()`, called at teardown, releases the sleeps and removes the folder.

`TestMesh` holds the sample values of the client tests: `local`, this device (`Sam's iPad`, id
`00000000-0000-4000-8000-0000000000A1`, `iPadOS`, version `1.0`, build 1); `main(_:id:)`, a Main of that name (`macOS`,
version `1.0`, build 1, a new id unless one is given); `record(_:addresses:port:updatedAt:revoked:)`, the `DeviceRecord`
of a device (for a Main only, the given addresses, none by default, and port, 47100 by default; `pairedAt`
2026-10-01T09:00:00.000Z; `updatedAt` 2026-10-29T08:00:00.000Z and not revoked unless given); `registry(_:)`, the
`MeshSnapshot` of the mesh of `testCredentials` holding each given Main with its one address, then this device, and no
presence; `hostInfo(_:forge:)` (projects folder `/Users/user/Developer`, Claude at `/Users/user/.local/bin/claude`,
Claude and git available, and the given `forge` config, none by default);
`summary(_:mainID:children:pendingPermissionCount:)`, `project(_:mainID:)` and `task(_:name:updated:)`: a project's
name is its identifier and its root `/Users/user/Developer/<id>`, its `created` the `pairedAt` above; a task is `Task`
unless named, `todo`, with no description and no comment, created at that `pairedAt` and updated at that `updatedAt`
unless given; and `fakeMain(_:registry:projects:forge:)`, a `FakeMain` answering `hello` with the device and the
registry, and `host.info` (`hostInfo(_:forge:)` with the given `forge`, none by default), `projects.list` (the given
projects), `skills.list` (no skill), `subscribe` and `unsubscribe`. The `XCTestCase` methods:
`makeEnvironment(fakeMains:credentials:registry:)` returns `TestEnvironment.make` (credentials `testCredentials` unless
given) and calls `removeFiles()` at teardown;
`startWorkspace(_:)` starts a `Workspace` of `TestMesh.local` on that environment and stops it at teardown;
`connectedWorkspace(projects:name:mainID:forge:configure:)` serves a Main (`Studio` unless named) at
`Sams-Mac-mini.local` with `fakeMain` (its `forge` passed on), which `configure` may change first, and returns the
Workspace, the `FakeMain` and the `TestEnvironment` once the connection is connected and its projects are loaded.

`TestPairingMain` plays the Main's side of a pairing window with `HephNet` alone: `PairingHost` belongs to
`MeshService` in `HephHost` ([devices/mesh.md](devices/mesh.md#pairing-window-main)), which `HephNetTests` cannot
import. `TestPairingMain` is an actor: `init(code: String, credentials: MeshCredentials, snapshot: MeshSnapshot) async
throws` starts a `WebSocketListener(port: 0, psk: MeshCrypto.pairingKey(code:), identity:
MeshConstants.pairingIdentity, host: "127.0.0.1")` and exposes its `port`. On the first channel (it closes any other)
it runs steps 1–4 of the Main's side of [devices/mesh.md](devices/mesh.md#exchange) with `PairingCodec`: it waits for
`pair.hello` and records the joiner's `DeviceInfo`; sends `pair.hello` with a Main's `DeviceInfo`, made from the first
record of the snapshot whose `isMain` is true (its id, name, `appVersion` and `build`, `isMain` true, platform
`macOS`), or a new Mac named `Test Main` when there is none, and the public key of an ephemeral
`Curve25519.KeyAgreement.PrivateKey`; derives `k` with `MeshCrypto.exchangeKey`; sends `pair.credentials` with
`MeshCrypto.seal` of the JSON (`WireCoding.makeEncoder()`) of `PairSecret {meshID, meshKey, snapshot}` from its
credentials and snapshot; waits for `pair.done`, records it and closes the channel, so `join` returns without waiting
its 5 s for the close. `stop()` stops the listener and closes the channel. `PairingHost` has no test of its own: the
pairing protocol is tested at this level.

`TestHost` (main actor) runs a `HostService` the way the host tests need it. `TestHost.start(prepare:beforeStart:)
async throws -> TestHost`, where `prepare: (TestHost.Folders) throws -> Void` and
`beforeStart: (DeviceIdentityStore) throws -> Void` default to doing nothing:

1. Creates three temporary folders: Application Support, projects and Trash.
2. `AppSupport(root:trashItem:)` on the first, whose `trashItem` moves the item into the Trash folder
   ([data/app-storage.md](data/app-storage.md#trash)); `SettingsStore(appSupport:)`, updated with `isMain` true and
   `projectsFolder` set to the projects folder; `DeviceIdentityStore(appSupport:settings:)`, which writes
   `device.json` ([devices/roles.md](devices/roles.md#deviceidentitystore)).
3. `prepare(TestHost.Folders(appSupport:projectsFolder:trashFolder:deviceID:))`, the three folder URLs and the id of
   the identity: a test writes there what the host must find at start (`projects.json` and project folders,
   `registry.json`, `migrations.json`).
4. `HostService(appSupport:settings:credentialStore:options:)` with `InMemoryCredentialStore(testCredentials)` and
   `HostOptions(listenerHost: "127.0.0.1", listenerPort: 0, bonjour: false)` ([services/host.md](services/host.md));
   then `beforeStart(<the DeviceIdentityStore>)`, which runs once the host and its `MeshService` exist, as onboarding
   runs after the app's launch created them; then `start()`.

Its properties are `host`, `identity` (the `DeviceIdentityStore`), `settings` (the `SettingsStore`), `port`
(`boundListenerPort()`, read after `start()`), `appSupport`, `projectsFolder` and `trashFolder`; `stop()` stops the host
and `removeFolders()` removes the folders, which are also removed when the `TestHost` is released. A test starts its
host with `startTestHost(prepare:beforeStart:)`, a method of `XCTestCase` in `HostTestSupport.swift` that calls
`TestHost.start(prepare:beforeStart:)` and adds a teardown block that stops the host and removes its folders.
`TestHost.deviceContext` is `RequestContext(device:connectionID:author:)` with a `DeviceInfo` of another device (a new
id, `Sam's iPad`, `iPadOS`, `isMain` false, version `1.0`, build 1), `connectionID` nil and `author` nil, for the cases
that call `host.perform(_:params:context:)` as a remote would; without a connection id it is an in-process call, which
the callers rule counts as a Main ([services/host.md](services/host.md) §4.4). `TestHost.claudeContext` is
`RequestContext.local(device: <the host's device>, author: "Claude")`, as the MCP tools call. `perform(_ method:
RPCMethod, _ params:, as:, context:)` encodes the params, calls `host.perform` with `deviceContext` unless another
context is given, and decodes the result as the given type.

`GitSandbox` (a class) runs git and bash for `PublicCheckTests` and `ForgePushTests`. `GitSandbox()` creates a
temporary folder, `folder` (removed at teardown), holding `home/`, `tmp/` and the folders of the repositories it makes.

- `environment`: exactly `PATH` = `/usr/bin:/bin:/usr/sbin:/sbin`, `HOME` = its `home/`, `TMPDIR` = its `tmp/`,
  `GIT_CONFIG_GLOBAL` = `/dev/null`, `GIT_CONFIG_NOSYSTEM` = `1`, `GIT_AUTHOR_NAME` and `GIT_COMMITTER_NAME` =
  `fixture`, `GIT_AUTHOR_EMAIL` and `GIT_COMMITTER_EMAIL` = `1+fixture@users.noreply.github.com`, `TZ` = `UTC`, and
  `HEPHAESTUS_PRIVATE_TERMS` = the path of `termsFile` when the case set terms (absent otherwise: the check then finds
  no terms file under `home/`). Nothing of the user's git configuration, identity or private terms is read.
- `termsFile`: `<folder>/private-terms.txt`. `terms: [String]?`: when set, the lines written to `termsFile`.
- `git(_ arguments: [String], in folder: URL, environment changes: [String: String] = [:]) throws -> String`
  (`@discardableResult`): `/usr/bin/git` with `environment`, in which `changes` sets variables for this command only
  (the e-mails of one commit in `testCommitIdentity` and `testTermInCommitEmail`, the temporary index of
  `testReplaceRefs`); returns its standard output, and a non-zero exit throws with its standard error.
- `check(_ arguments: [String], in folder: URL, environment changes: [String: String] = [:]) throws -> (status: Int32,
  output: String, error: String)`: `/bin/bash <repositoryRoot>/scripts/check-public.sh <arguments>` in `folder`, with
  `environment`, in which `changes` sets variables for this run only (`testAttributesIgnored`, `testMessage`).
- `outputs: [String]` (read-only): the standard output, then the standard error, of each process the sandbox ran
  (`git` and `check`, failed ones included), in order. `testNothingLeaks` reads all of them; `testHooks` reads those
  of the last process, since the pre-push hook writes to git's standard output (verified with git 2.54), which
  `git(_:in:environment:)` does not return when it throws.
- `makeRepository() throws -> URL`: a new folder, `git init -b main`, the repository's `scripts/check-public.sh` and
  `.githooks/` copied from `repositoryRoot` with mode 755, committed (`initial`).
- `makeOrigin(of repository: URL) throws -> URL`: a bare repository (`git init --bare -b main`), added to `repository`
  as `origin`, and `main` pushed to it.

## Fixtures

JSON object per line. Each `.jsonl` holds the CLI's standard output lines in the order received; each `.stdin.jsonl`
holds the lines written to its standard input, in order.

| Any other temporary path                                                                              | `/tmp/claude`                                                                                                  |
| `/Users/<user name>`                                                                                  | `/Users/user`                                                                                                  |
| The account email                                                                                     | `user@example.com`                                                                                             |
| The `initialize` response's `account`, `pid`, `models` and `agents`                                   | removed                                                                                                        |

| `system/init`: `startup_timing`, `memory_paths`, `messaging_socket_path`                              | removed                                                                                                        |
| `system/init`: `mcp_servers`                                                                          | `[]`                                                                                                           |
| `system/init`: the items of `tools` that start with `mcp__`                                           | removed                                                                                                        |
| `system/init`: `slash_commands`, `skills`, `plugins`, `agents`                                        | `["compact","review"]`, `[]`, `[]`, `["general-purpose"]`                                                      |

Other values that start the same way are kept: the control request id `req_init`, which the parser tests expect, and
the capability name `msg_lifecycle_v1`. Lines are written as compact JSON (`separators=(",", ":")`). Fixtures are
recorded again only when the CLI's output format changes; the expectations below then follow the new recordings.

### HephUISnapshotTests

`ScreenSnapshotTests` (macOS): for each `SidebarSection` except `web`, the window content of [ui/shell.md](ui/shell.md)
gets the environment of a window from the preview helpers of [ui/shell.md](ui/shell.md#54-previews): one
`AppModel.preview()` (never started; its `workspace` is `Workspace.preview()`) and
`.previewWindow(appModel, selection:)`, which injects the `AppModel`, a `WindowContext` with its `Selection` and
`WindowBanners`, the `Workspace`, the `SettingsStore` and the `UpdateModel`. The selection is on Studio, project `HEPH`
(project sections) or no project (workspace sections), with no item. `web` is left out: the `.task` of its
`WebTabsView` ([ui/web.md](ui/web.md)) creates the active tab's web view, which loads the web tabs of the preview
workspace (`https://github.com/Azavech/Hephaestus`, `https://forums.swift.org`) over the network.

The test first calls `NSApplication.shared.setActivationPolicy(.prohibited)`, so the test process gets no Dock icon.
For each section:

1. `MainShell().previewWindow(appModel, selection:)` is the root view of an `NSHostingView`, set as the `contentView`
   of an `NSWindow(contentRect:styleMask:backing:defer:)` with the rect of 1280 × 800 points at the origin,
   `[.titled, .resizable, .fullSizeContentView]`, `.buffered` and `false`. The window is never ordered in, so nothing
   appears on screen.
2. `layoutSubtreeIfNeeded()` on the hosting view; the main run loop runs for 1 s (`RunLoop.main.run(until:)`), so the
   views' tasks run; `layoutSubtreeIfNeeded()` again.
3. `cacheDisplay(in: hosting.bounds, to:)` draws the hosting view into
   `NSBitmapImageRep(bitmapDataPlanes: nil, pixelsWide: 2560, pixelsHigh: 1600, bitsPerSample: 8, samplesPerPixel: 4,
   hasAlpha: true, isPlanar: false, colorSpaceName: .deviceRGB, bytesPerRow: 0, bitsPerPixel: 0)`, whose `size` is
   set to 1280 × 800 points.
4. Assertions: `window.isVisible` is false, and the drawing is not of one color: among the pixels whose x and y are
   both multiples of 40, `colorAt(x:y:)` finds at least two different colors.
5. The PNG (`representation(using: .png, properties: [:])`) is written to
   `$TMPDIR/HephaestusSnapshots/<section>.png`, and the window's `contentView` is set to nil.

The PNGs show each section's content with the sample data; the sidebar comes out blank. The teardown removes the
folder of `appModel.appSupport`; the PNGs stay.
